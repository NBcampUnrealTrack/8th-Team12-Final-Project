# NPC 회피: RVO vs 직접 만든 회피

햄버거집 손님(BurgerHouse)과 행인(SubNpc)은 서로 다른 방식으로 "부딪히지 않기"를 푼다.
이 문서는 언리얼 내장 RVO가 무엇인지, 두 NPC가 각각 왜 그 방식을 골랐는지 정리한다.

---

## 1. RVO란

**RVO (Reciprocal Velocity Obstacles)** — 부딪히기 전에 **속도를 틀어서 서로 비켜 가는** 회피 알고리즘.

- 언리얼 엔진에 **내장**되어 있다. 플러그인·외부 라이브러리 설치 없이 `CharacterMovementComponent`의
  체크박스 하나(`bUseRVOAvoidance`)로 켠다.
- 켠 캐릭터는 월드의 `UAvoidanceManager`에 등록되고, **등록된 캐릭터끼리만** 서로를 계산한다.
- 경로를 다시 찾는 게 아니라, 매 틱 "가려던 속도"를 충돌 코스에서 살짝 비튼다.
- Reciprocal = 양쪽이 나눠서 비킨다. `AvoidanceWeight`로 누가 더 비킬지 비율을 정한다.

### 바로 쓸 수 있나?

체크박스는 바로 켤 수 있지만, **동작하려면 조건이 있다.**

| 조건 | 이유 |
|---|---|
| `CharacterMovementComponent`가 **틱을 돌아야** 한다 | RVO 계산이 이 컴포넌트의 이동 처리 안에서 일어난다 |
| 이동이 **속도 기반**이어야 한다 (AI MoveTo, `AddMovementInput` 등) | 틀어 줄 "속도"가 있어야 한다. 위치를 직접 세팅하면 개입할 틈이 없다 |
| 피해야 할 상대도 **RVO를 켜야** 한다 | 꺼진 캐릭터는 매니저에 없으므로 투명 인간 취급 |

조건만 맞으면 코드 한 줄 없이 동작한다. 같은 엔진 내장 대안으로는 AIController용
**Detour Crowd** (`UCrowdFollowingComponent`)가 있다.

---

## 2. 켰을 때 장단점

| 장점 | 단점 |
|---|---|
| 체크박스 하나 — 구현 비용 거의 0 | **켠 캐릭터끼리만** 피한다. 끈 캐릭터·지형·소품은 못 본다 |
| 마주 오는 캐릭터끼리 자연스럽게 엇갈린다 | 경로를 다시 찾지 않는다 → 좁은 통로·막다른 곳에서 서로 밀다 멈추거나 떨린다 |
| 이동 방식과 무관하게 "결과 속도"에 걸려 붙이기 쉽다 | 내비메시를 모른 채 속도를 틀어 내비 밖으로 살짝 밀려날 수 있다 |
| | **켠 캐릭터 자신의 움직임도 바뀐다** — 플레이어에게 켜면 입력 방향과 실제 이동이 어긋나 미끄러지는 조작감 |
| | 인원이 많으면 주변 쌍 계산 비용이 늘어난다 |

## 3. 햄버거집 손님 (BurgerHouse)

| 항목 | 값 |
|---|---|
| 손님 `BP_Customer` | **RVO 켜짐** (고려 반경 200, `AvoidanceWeight` 0, 속도 350) |
| 플레이어 `BP_CHeon` | **RVO 꺼짐** (속도 500) |
| 이동 | 내비메시 + StateTree `Move To` (AIController) |
| 인원 | 정원 8명 |

- 손님끼리는 잘 비킨다.
- 플레이어는 RVO가 꺼져 있어 손님에게 **보이지 않는 벽**이다. 플레이어가 동선을 막으면
  손님은 캡슐에 대고 걸으며 멈추고, `Move To`에 시간 제한이 없어 다음 단계로 못 넘어간다.
- 플레이어 RVO를 켜면 해결되지만, `BP_CHeon`은 모든 레벨 공용이라 조작감이 바뀌는 위험이 있다.

**결론** — 소수 · 내비 기반 · AIController NPC에게 RVO는 싸고 적당한 선택.
단, 플레이어까지 피하게 하려면 플레이어도 RVO에 참여해야 한다는 한계가 있다.

## 4. 행인 (SubNpc)

### 4-1. CharacterMovement 틱을 꺼서 아끼는 것

행인은 `CharacterMovementComponent`를 **틱째로 꺼 둔다** (`SubNpcCharacter.cpp` 생성자).
이동은 감독(`SubNpcDirectorSubsystem`)이 스플라인 위 진행 거리를 직접 계산해 위치를 세팅한다.

기능을 없앤 게 아니라, **범용 처리를 빼고 행인에게 필요한 만큼만 가볍게 다시 만들었다.**

| 기능 | CharacterMovement (범용) | 행인 (직접 구현, `SubNpcCharacter.cpp`) |
|---|---|---|
| 중력 → 바닥에 서기 | 속도·가속으로 낙하 시뮬레이션 + 매 틱 바닥 찾기 캡슐 스윕, 걷기/낙하 모드 전환 | **`GroundSnap`** — 발밑으로 라인 트레이스 1회, 맞은 높이에 바로 붙인다. 낙하 시뮬레이션 없음. 계단·경사로도 OK |
| 벽 막힘 | 이동 캡슐 스윕 + 벽 따라 미끄러짐, 모든 충돌 채널 대상 | **`WorldBlock`** — 지형(WorldStatic/Dynamic)만 캡슐 스윕 1회. 45cm 이하 턱·45° 이하 경사는 통과. 막히면 차선을 길 가운데로 당김 |
| 사람끼리 충돌 | 캡슐끼리 막힘 (정체 발생) | 일부러 **막지 않음** — 대신 속도 회피·겹침 금지로 처리 (4-2) |
| 적용 범위 | 모든 개체, 매 프레임 | **가까운 개체만** (WorldBlock은 Near·Mid LOD만). 멀리 있는 행인은 생략 |
| 그 외 | 물리 볼륨(물·중력 구역) 판정, RVO 등 | 필요 없어서 없음 |

- 측정값 (100명, 2026-10-06 기준선): 군중 로직 전체 **0.85ms**, 1명당 **약 8.5µs**
  (이동 0.786ms 중 GroundSnap 0.179 · WorldBlock 0.143 포함)
- 각각 콘솔 변수로 끌 수 있다: `crowd.GroundSnap 0`, `crowd.WorldBlock 0`

> CharacterMovement를 켠 상태와의 직접 A/B 측정은 하지 않았다.
> 다만 일반적으로 걷는 캐릭터 1명의 CharacterMovement 틱은 바닥 스윕·이동 스윕 때문에
> 행인 군중 로직 1명분(8.5µs)보다 무겁고, 이 비용이 인원 수에 그대로 비례한다.

### 4-2. RVO 대신 직접 만든 회피

틱이 꺼져 있으니 RVO는 켜도 동작하지 않는다 (코드에서도 `bUseRVOAvoidance = false` 명시).
대신 감독이 회피를 직접 한다.

| 구간 | 내용 | 100명 비용 |
|---|---|---:|
| `Avoidance` | 0.1초마다 가까운 쌍(최대 128쌍)을 골라 감속·옆으로 비키기. 우측 통행, 직전 선택 유지 | 0.040ms |
| `BodySeparation` | 매 프레임 몸 겹침 금지. 닿기 직전이면 뒷사람을 세운다 | 0.023ms |
| 플레이어 | **장애물로 포함** (`AvoidPlayerMargin` 20cm) — 플레이어 RVO 설정과 무관 | (위에 포함) |

### 4-3. 행인에게 RVO를 쓴다면

| | 직접 만든 회피 (현재) | RVO로 바꾸면 |
|---|---|---|
| 플레이어 회피 | 된다 | 플레이어도 RVO를 켜야 함 → 조작감 문제 |
| 비용 | CharacterMovement 꺼짐 · 분할 갱신 · 쌍 예산 | 행인마다 CharacterMovement 틱 부활 → 성능 작업과 정면 충돌 |
| 길 규칙 | 우측 통행 · 선택 유지 · 스팟/줄 사람 양보 | 속도만 비킨다. 길·줄 개념 없음 |
| Mass · 원경 인스턴스 | 감독 한 곳에서 처리 → 일관됨 | 액터 컴포넌트 기준이라 Mass·인스턴스 경로와 따로 논다 |

**결론** — 수백 명 · 직접 계산 이동 군중에게 RVO는 맞지 않는다.
직접 만든 회피가 더 싸고, 플레이어까지 피하며, 길 위 규칙도 넣을 수 있다.

## 5. 한 장 요약

| | 햄버거집 손님 | 행인 |
|---|---|---|
| 규모 | 8명 | 수백 명 |
| 이동 | 내비메시 + AI MoveTo | 스플라인 진행 거리 직접 계산 |
| CharacterMovement | 켜짐 | **틱 꺼짐** — 중력·벽은 가벼운 직접 구현(GroundSnap·WorldBlock)으로 대체 |
| 회피 | 엔진 RVO (체크박스) | 직접 구현 (속도 회피 + 겹침 금지) |
| 플레이어 회피 | 안 됨 (플레이어 RVO 꺼짐) | 됨 |
| 선택 이유 | 적은 인원 — 구현 비용 최소 | 많은 인원 — 실행 비용 최소 |

**핵심**: RVO는 "구현 비용"을 아끼는 도구, 직접 만든 회피는 "실행 비용"을 아끼는 도구.
규모가 작으면 전자, 크면 후자.
