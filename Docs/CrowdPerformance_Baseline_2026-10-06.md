# 군중(행인) 성능 기준 측정 — Mass 도입 전

- 측정일: 2026-10-06
- 대상: 액터 기반 행인 (`ASubNpcCharacter` + `USubNpcDirectorSubsystem`), 브랜치 `feature/npc_upgrade`
- 목적: Mass Entity로 옮기기 전 기준값 확보. 같은 명령(`crowd.Bench`)으로 Mass 적용 후 다시 재서 비교한다.

## 1. 측정 방법

```
crowd.Bench <인원...> [secs=20] [warmup=5] [label=이름]
```

- 단계마다 인원을 즉시 맞추고 5초 안정화 → 20초 측정.
- 결과
  - 로그 `[CrowdBench]` : 인원별 프레임 시간, 군중 구간별 ms
  - `Saved/Profiling/CrowdBench/Summary_*.csv` : 요약
  - `Saved/Profiling/CSV/CrowdBench_*_N###.csv` : 단계별 CSV 프로파일러 캡처 (게임/렌더/GPU 스레드 포함)
- 군중 구간 표식 (Insights `Crowd_*`, CSV `Crowd/GameThread/*`)

| 구간 | 내용 |
|---|---|
| PathFollow | 행인 1명의 경로 이동 전체 (GroundSnap, WorldBlock 포함) |
| GroundSnap | 지면 스냅 라인 트레이스 |
| WorldBlock | 벽 캡슐 스윕 |
| Avoidance | 차선 계획·회피 (0.1초마다) |
| BodySeparation | 몸 겹침 금지 (매 프레임) |
| GroupLogic | 일행 대화·대열·길 밖 양보 |
| LodSlice | LOD 재계산 |

## 2. 측정 조건과 한계 (결과를 읽기 전에 꼭 볼 것)

| 항목 | 이번 측정 | 영향 |
|---|---|---|
| 실행 방식 | PIE (에디터 뷰포트) | 에디터 UI(Slate) 비용 약 3.3~4.0ms가 게임 스레드에 섞임 |
| 프레임 제한 | 60 FPS(16.67ms)에 묶임 (에디터 수직동기) | **FPS·프레임 시간으로는 여유를 알 수 없음.** 스레드별 시간으로 판단 |
| 측정 순서 | 단계마다 따로 실행 (0 / 30 / 60 / 100) | 요약 파일이 단계별로 나뉨 |
| 0명 단계 | 일부 프레임이 창 포커스 이탈로 느려짐 (FrameTime p95 50ms) | 0명 단계의 렌더 스레드 값은 신뢰 낮음 |
| 경로 밀도 | 경로 총 길이 약 74m에 100명 → 1.36명/m | 정체가 심함 (권장 0.3~0.5명/m). 비용보다는 움직임 품질 문제 |

수치는 CSV 캡처의 **중앙값**(튀는 프레임 제외)을 썼다. 회피(Avoidance)는 0.1초마다 돌아 중앙값이 0이므로 `[CrowdBench]` 로그의 프레임당 평균을 썼다.

## 4. 해석

1. **군중 로직 자체는 싸다.** 100명에 0.85ms로 게임 스레드의 약 7%다. Mass로 로직만 옮겨서 아낄 수 있는 건 이 0.85ms에 액터 틱 오버헤드 일부(약 1ms)를 더한 **최대 2ms 정도**다.
2. **인원이 늘 때 커지는 비용은 애니메이션과 렌더링이다.**
   - 애니메이션 워커 4.3ms, 게임 스레드 애니메이션 1.1ms, GPU +2.3ms (100명 기준)
   - 메타휴먼 스켈레탈 메시라 1명당 비용이 크다.
3. **가장 먼저 한계에 닿는 것은 GPU다.** 100명에서 GPU 13.4ms로 60 FPS 예산(16.6ms)에 가장 가깝다.
   - 단순 직선 외삽: GPU는 약 **240명**, 게임 스레드(에디터 UI 제외)는 약 **340명**에서 16.6ms에 닿는다.
   - 외삽값이고 프레임 제한이 걸린 PIE 측정이라 참고용이다.
4. 그러므로 Mass를 넣는다면 목적은 "지금 100명을 빠르게"가 아니라 다음이어야 효과가 있다.
   - **인원을 수백 명으로 늘린다** — 로직·틱 비용이 개체 수에 비례해 커지기 전에 Mass로 옮긴다.
   - **표현(Representation) LOD** — 가까운 사람만 지금의 스켈레탈 메시 액터, 멀리 있는 사람은 인스턴스드 스태틱 메시 + 버텍스 애니메이션(AnimToTexture)으로 그려 애니메이션·GPU 비용을 없앤다. 이게 비용 대부분을 줄이는 부분이다.
5. Mass 없이도 바로 해볼 수 있는 것
   - GroundSnap + WorldBlock이 PathFollow의 41%(0.32ms/100명). Mid 거리는 지면 스냅 주기를 낮추는 식으로 줄일 수 있다.
   - 애니메이션: Mid/Far의 `URO`(업데이트 레이트) 프레임 스킵을 더 크게, 화면 밖은 포즈 평가 끄기.

## 5. 다음 측정 (정확한 값 얻기)

이번 값은 PIE + 60 FPS 제한이라 상한을 모른다. 다음 측정은 아래 조건으로 다시 한다.

1. **Standalone Game**(또는 Development 패키지)으로 실행 — 에디터 UI 비용 제거.
2. 한 번에 실행: `crowd.Bench 0 30 60 100 150 200 label=Base`
   - `crowd.Bench`가 측정 동안 `t.MaxFPS 0`, `r.VSync 0`, `r.VSyncEditor 0`을 걸고 끝나면 되돌린다.
3. 측정 동안 게임 창을 포커스한 채 두고 카메라를 움직이지 않는다 (3 FPS로 묶이면 로그에 경고가 뜬다).
4. 원인 분리 비교 (`label`만 바꿔서)
   - `crowd.LOD 0` → `label=LodOff` : LOD가 아껴 주는 양
   - `crowd.Avoidance 0` → `label=AvoidOff` : 회피 비용
   - `crowd.WorldBlock 0` → `label=WorldBlockOff` : 벽 스윕 비용
5. Mass 적용 후 같은 조건으로 `label=Mass` 측정 → 이 문서의 표와 비교.
